# 自动日报与飞书推送（v0.10.0）

> 位置：**🔍 选股模块 → 「自动日报」子页**
> 代码：`daily_report.py`（汇总/定时判定）、`feishu.py`（飞书机器人）、
> `ui/scan_center.py`（界面与调度）、`workers.py`（`auto_scan_done` 信号）

---

## 一、它做什么

每天定时（默认 15:30）跑一次 **盘前/盘后全市场扫描**：

1. 用全部「盘前盘后全市场」节奏的**启用策略**跑一遍全市场（含二层 DNA 串联）；
2. 扫描结束（`auto_scan_done`）后，把当天**所有策略**的命中结果汇总成 Markdown 文档；
3. 通过**飞书自定义机器人**把精简版推到群里，完整版存本地。

信号日**固定取某一天**（`start_date = end_date = 该日`），不会像手动扫描那样跑一整段区间；
该日由 `resolve_scan_date()` 决定，今天没有日K就自动回退到最近交易日（见第三节）。

## 二、两种推送方式（v0.10.2）

界面上「推送方式」下拉框二选一，填错的一组输入框会自动置灰。

| 方式 | 需要的信息 | 适用 |
|---|---|---|
| **自建应用机器人**（默认） | App ID + App Secret + 接收方 ID | 已有飞书自建应用；能发到群也能发到个人；权限可控 |
| **自定义机器人**（Webhook） | 一条 Webhook 地址（+ 可选签名密钥） | 只想快速发到某个群，不想建应用 |

### 方式 A：自建应用机器人（app_id + app_secret + receive_id）

这条链路是：`app_id + app_secret` → 换 `tenant_access_token` → 调
`POST /open-apis/im/v1/messages?receive_id_type=chat_id` 发消息。

**准备（在飞书开放平台开发者后台）：**

1. 找到你的自建应用 → 「凭证与基础信息」→ 复制 **App ID** 和 **App Secret**；
2. 「权限管理」里开通 **`im:message:send_as_bot`**（以应用身份发消息）；
3. 「版本管理与发布」→ 创建版本并**发布**（权限改完不发布不生效）；
4. 把该应用机器人**拉进目标群**（群设置 → 群机器人 → 添加机器人 → 选你的应用）；
5. 拿**接收方 ID**：
   - 发群：群 `chat_id`，`oc_` 开头（你现在这串 `oc_b415...` 就是）；
   - 发个人：用户 `open_id`（`ou_` 开头）或 `user_id` / 邮箱。

**在程序里填：**

| 控件 | 填什么 |
|---|---|
| App ID / App Secret | 上一步复制的 |
| 接收方 | `oc_...` / `ou_...` / 邮箱 |
| 类型 | 与接收方匹配：群 chat_id / 用户 open_id / 用户 user_id / 邮箱 |

### 方式 B：自定义机器人（Webhook）

飞书群 → 群设置 → 群机器人 → 添加机器人 → **自定义机器人**：

- 复制 **Webhook 地址**（`https://open.feishu.cn/open-apis/bot/v2/hook/xxxx`）；
  只粘最后那串 token 也能用，程序会自动补全；
- 安全设置三选一：**自定义关键词**（当前标题含「选股日报」，可用这个）/
  **签名校验**（把密钥填到「签名密钥」）/ **IP 白名单**。

### 其它配置项

| 控件 | 说明 |
|---|---|
| 启用每日定时扫描 | 关掉就只保留手动按钮 |
| 执行时间 | 默认 15:30（收盘后），必须晚于收盘才有当日数据 |
| 仅工作日 | 周末不跑 |
| 启动时补跑当天 | 见下一节 |
| 每策略最多列 | 飞书消息里每个策略列几只（默认 10，完整清单在本地文档） |
| 含观察池 / 含提醒 / 保存本地文档 | 报告内容开关 |

填完点 **保存配置**，再点 **测试发送** 验证能收到消息。

### 3. 三个按钮

| 按钮 | 行为 |
|---|---|
| 保存配置 | 写入 `settings` 表 |
| 立即扫描并推送 | 马上跑一次全市场扫描，结束后生成+推送（不影响定时任务的「今日已执行」记录） |
| 只生成日报并推送 | **不重新扫描**，直接用数据库里当天已有的结果生成+推送（想先看效果时用这个） |

## 三、定时与补跑

- 主界面每 30 秒检查一次；到点且当天没执行过就启动。
- **宽限期 2 小时**：例如设 15:30，程序 16:40 才打开也会自动跑；
  超过 2 小时则不跑（避免晚上开程序时突然跑一次全市场）。
- 勾选 **启动时补跑当天** 后，超过宽限期也会补执行一次。
- 只有「定时/补跑」触发的任务才会写入「上次执行」；手动触发不会顶掉当天的定时任务。

### 信号日怎么定（v0.10.3）

> 定时任务**不看**工具条上的「信号日期」——那一栏只对**手动**扫描生效。

定时任务自己判断该跑哪一天：

1. 本地缓存已有今天的日K → **跑今天**；
2. 没有 → 探测 3 只代表性标的（贵州茅台 / 平安银行 / 中国平安）的最新K线日期；
3. 探测到今天 → **跑今天**；
4. 只探测到更早的日期 → **自动回退到那个交易日**，运行日志写：
   `⚠ 今天（2026-11-24）还没有日K（非交易日或行情未落地），自动回退到最近交易日 2026-11-21`；
5. 探测全部失败 → 用缓存里最近的日期；连缓存都没有 → 按今天跑。

扫描结束后还会回报当日日K覆盖度：`2026-11-21 日K缓存覆盖 5213 只`；
覆盖低于 1000 只会提示「覆盖偏低：当天行情可能未完全落地或取数失败，结果会偏少」。

这样处理后：**法定节假日不会推空报告**，收盘数据没及时落地也会退到上一个交易日重跑。

> ⚠️ 这是桌面程序的**进程内定时**：程序必须处于运行状态。若希望关掉程序也能跑，
> 需要用 Windows 任务计划程序定时启动 `main.py`（当前未集成）。

## 四、报告内容

### 本地文档
`reports/日报-YYYY-MM-DD.md`，结构：

```
# 选股日报 · 2026-11-23
- 生成时间 / 统计策略数 / 命中合计 / 市场宽度
## 一、一层粗筛
### 策略名（N 只）
| 代码 | 名称 | 收盘 | 涨幅 | 命中说明 |   ← 前 10 只
> 其余 N 只未逐条列出
## 二、二层精筛
### 策略名（N 只）
| 代码 | 名称 | 综合分 | 骨架分 | 买点定级 | 最佳模具 | 收盘 |
## 三、观察池（当日新增）
## 四、提醒（当日触发）
```

### 飞书消息
`msg_type = post`（富文本），标题 `📊 选股日报 YYYY-MM-DD`，正文为纯文本行；
超过 6000 字自动截断并提示，推送失败会自动降级为纯文本重试一次。
开启 AI 点评后，消息开头会多一段 `【AI 点评】`。

## 五、AI 点评（v0.10.4，可选）

勾选「启用 AI 点评」后，程序把当日汇总交给大模型，让它**按你的策略体系**写一段点评，
追加到本地日报（`## 五、AI 点评`）并放在飞书消息最前面。

### 支持的端点（任意 OpenAI 兼容接口）

| 服务 | Base URL | 模型示例 |
|---|---|---|
| 火山方舟 | `https://ark.cn-beijing.volces.com/api/v3`（默认） | `doubao-seed-1-6-250615` 或推理接入点 `ep-xxxx` |
| DeepSeek | `https://api.deepseek.com/v1` | `deepseek-chat` |
| Moonshot | `https://api.moonshot.cn/v1` | `moonshot-v1-8k` |
| 本地 Ollama | `http://localhost:11434/v1` | `qwen2.5:14b` |

填好 Base URL / 模型 / API Key 后点 **测试 AI**，通了会回一句「AI 可用」。

### 喂给模型什么

**只喂汇总，不喂全量**（控制 4000 字以内）：日期、市场宽度（涨跌家数/平均涨幅）、
总命中数、按「二层 → 一层」分组的各策略命中数与**前 N 只**明细（默认 8 只，
二层带综合分/骨架分/买点定级/模具名）、当日入池数量，以及

**【跨策略共振】名单** —— 同一只票被 ≥2 个策略同时命中时单独列出（最多 10 只）。
这是整份上下文里信息密度最高的一段：一只票同时出现在「B1海选 + 二层通过」或
「砖型 + B2」里，比任何单策略命中都可信，模型被告知优先采用。

### 模型被要求怎么写

系统提示里注入了你的策略语义，并要求：

- 纯文本、不用 Markdown、每行 ≤40 汉字、总长 ≤500 字；
- 结构固定：一句话信号结构 → 3~5 只重点标的（`代码 名称：理由`）→ 一行风险提示；
- **只用给定数字，禁止编造**代码/价格/指标；不给买卖点位、不承诺收益。

优先级它被要求遵守：**二层通过 > 一层与 B2 共振 > 单策略大量命中里的代表**。

### 失败怎么办

AI 超时、报错、返回空内容时，**只跳过点评，日报照常生成和推送**，
运行日志里写 `✗ AI 点评失败：<原因>`。常见原因：

| 提示 | 处理 |
|---|---|
| `认证失败（401）` | API Key 不对或失效 |
| `无权限（403）` | Key 没开通该模型 |
| `接口不存在（404）` | Base URL 或模型名写错 |
| `网络异常` | 本机网络 / 端点不通 |

### 配置项存储

`settings` 表：`ai_enabled` / `ai_base_url` / `ai_api_key` / `ai_model` /
`ai_max_tokens` / `ai_timeout` / `ai_prompt_extra`（额外要求会追加到系统提示）。

> 注意：API Key 以明文存在本地 SQLite 里（与飞书 App Secret 同样处理），
> 不要把 `trade_assistant.db` 分享给别人。

## 六、实现要点

- **同策略多次扫描只取最近一次会话**：当天手动重跑、二层父策略重跑都会产生多个
  `session_id`，日报按 `(strategy_id, layer)` 取最新会话，避免重复计数
  （`daily_report._latest_sessions`）。
- **市场宽度**：`Database.get_market_breadth(day)` 用 `daily_bars_cache` 的
  「该日收盘 vs 上一交易日收盘」统计涨跌家数与平均涨幅，只取前后 30 天窗口。
- **推送不阻塞界面**：网络请求在后台线程执行，结果通过 `report_sent` 信号回到主线程。
- **失败自愈**：扫描报错时复位 `_daily_pending`，不会把后续定时永久卡死；
  股票列表未就绪时每 20 秒重试，最多 30 次。
- **性能**：`scan_history` 增加表达式索引
  `idx_scan_history_day(COALESCE(trade_date, date(scan_time)))`，
  按信号日查询从 7.2 秒降到 0.02 秒（8 万行库实测）。

## 七、常见问题

| 现象 | 处理 |
|---|---|
| `Invalid URL 'oc_xxx': No scheme supplied` | 用自定义机器人方式时只粘了 token。**v0.10.1 起自动补全**；但如果你本来就是走应用机器人，应该把 `oc_xxx` 填到「接收方」而不是 Webhook |
| `换取 token 失败 10014（app_secret 不正确）` | App Secret 复制不全或有空格 |
| `飞书返回错误 99991672` | 应用缺少发消息权限：开通 `im:message:send_as_bot` 并**发布版本** |
| `飞书返回错误 230002` | 机器人不在该群：把应用机器人拉进群，或检查 chat_id |
| `飞书返回错误 230013` | 用户不在应用可用范围（开发者后台 → 权限 → 可用范围） |
| 自定义机器人 `HTTP 403` / `code 19021` | 关键词没命中、签名密钥错、IP 不在白名单（错误信息已带中文提示） |
| `code 19001` Webhook 地址不对 | 复制到的可能不是机器人地址（例如群 ID），回群设置重新复制 |
| 群里没收到但有「推送成功」 | 看的是另一个群，核对接收方 ID 尾部（日志里会打码显示） |
| 到点没跑 | 检查「启用」是否勾选、当天是否已执行、是否过了 2 小时宽限（看子页运行日志） |
| 日报里某策略 0 只 | 该策略当天没命中；若全部为 0，检查是否行情源故障（`logs/app.log` 的「网络取数失败」） |
| 想要更多明细 | 调大「每策略最多列」，或直接看 `reports/` 下的完整文档 |
