# 功能盘点与用户故事地图

> 目的：用软件开发的标准管理方法，把现有所有功能"摆出来"，
> 回答两个问题：**① 系统里到底有什么 ② 你真正需要的有没有被实现**。
>
> 方法组合（推荐流程）：
> 1. **功能清单（Feature Inventory）**——本文档第二节，全量盘点 ✅ 已完成
> 2. **用户故事地图（User Story Map）**——本文档第三节，按使用流程摆功能 ✅ 已完成
> 3. **需求追溯矩阵（Traceability Matrix）**——本文档第四节，需求↔功能↔代码↔测试 ✅ 已完成
> 4. **功能使用埋点（Usage Analytics）**——第五节方案，需用户同意后实施 ⏳ 待拍板
> 5. **MoSCoW 优先级**——第六节，数据到手后拍板砍留 ⏳ 最后执行
>
> 状态：2026-08-15 盘点完成；**F027/F056 可视化条件已拍板移除（v0.6.3）**；埋点方案待用户确认。

共盘点 **57 项功能（F001-F057）**，状态分布：

## 五、功能使用埋点方案（待确认）

> 原理：**"你觉得你需要"和"你实际在用"经常是两回事**。与其猜，不如让软件自己记录。
> 互联网产品的标准做法，本地单机应用同样适用，而且更简单。

### 设计（很小，约 1 小时工作量）

1. **新表** `usage_log(id, ts, tab, action, detail)`；
2. **页签切换埋点**：`main_window.py` 的 QTabWidget 加 `currentChanged` 连接，记录"几点几分切到哪个页签"——这个最重要，能看出每天每个页签停留/打开次数；
3. **关键按钮埋点**：约 15-20 个高频动作（加入观察池、确认入池、记录交易、扫描、诊断、当日总结、内置库、推送测试、策略新增/编辑……）各加一行 `log_usage(...)` 调用；
4. **自动任务埋点**：提醒触发、推送、扫描命中（已有日志，可直接关联）；
5. **导出脚本** `usage_report.py`：按功能聚合"次数/最近使用日期/日均"，生成统计文本/表格。

### 运行方式

- 正常使用 **1~2 周**（覆盖至少 2-3 个交易日）；
- 然后跑 `usage_report.py` 出报表；
- 报表 + 功能清单的"使用率假设"列对照：**实际数据打脸猜测**的地方，就是该砍/该留的证据；
- 最后用 MoSCoW（Must/Should/Could/Won't）逐项拍板。

### 风险

- 纯本地 SQLite 写入，不联网、不采集隐私，无性能影响（每次一条 INSERT）；
- 完全可逆：删表即可。
