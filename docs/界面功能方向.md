# 界面功能方向定义（v0.7 设计）

> 目的：把"每个界面到底负责什么、不负责什么"定死，避免功能错位。
> 触发原因：用户明确系统定位 = **辅助大A监测系统**（跑策略、监控、提醒、盯机会），
> **不是**通达信/同花顺式的全局看盘软件。
>
> 状态：2026-08-15 由用户口述方向整理；Q1/Q2/Q3 均已拍板；
> v0.6.5 已实施提醒联动与策略编号/版本归档；**v0.6.6 已实施行情日历（T015）**。

---

## 一、总体原则

1. **一切围绕策略**：每个界面要么产出策略结果、要么消费策略结果、要么管理策略本身。
   不做"无目的的行情浏览"。
2. **以每日为单位**：复盘视角从"实时列表"转向"每日归档"（行情日历是核心体现）。
3. **界面统一性**：功能近似的子界面必须用统一组件，不各做一套：
   - 所有"命中/股票列表"→ 统一 **命中列表组件**（第六节）
   - 所有"加入观察池"→ 统一走观察池的加入对话框
   - 所有"K线/诊断"→ 统一 ChartDialog / DiagnoseDialog
4. **数据层保留**：实时行情数据（quotes）仍是盘中扫描候选排序的基础，
   只是不再有"实时行情页签"；改为后台按需拉取（行情快照服务化）。

## 二、六个页签的功能方向（目标版）

| # | 页签 | 定位（一句话） | 核心内容 | 明确不做 |
|---|------|--------------|---------|---------|
| 1 | 📅 行情日历 | 以每日为单位，归档"当日符合策略的股票"，历史回溯的入口 | 月历视图 + 每日命中清单 | 不做实时行情表/量比/涨速/排序浏览 |
| 2 | 👀 观察池 | 候选股票的跟踪与交易执行 | 现状保留 | — |
| 3 | 🔔 提醒设置 | 盯住机会的"哨兵"：价格/指标/策略信号，触发即推 | 现状 6 类提醒 + **新增"策略信号"类**（联动策略管理） | — |
| 4 | 🎯 策略管理 | 策略资产的增删改查、说明书、诊断（本版不动） | 现状保留 | 本版不修改 |
| 5 | 🔍 扫描中心 | 策略的执行器：批量扫描、命中历史、当日总结 | 现状保留；命中列表换成统一组件 | — |
| 6 | 📒 交易记录 | 决策日记 + 轻量统计 | 现状保留 | — |

**页签顺序调整**：①行情日历 ②观察池 ③提醒设置 ④策略管理 ⑤扫描中心 ⑥交易记录
（提醒设置从第 6 位移到第 3 位，因为它是盘中核心哨兵）。

## 三、行情日历（替换实时行情页签）详细设计

### 3.1 视图结构（页签内两级导航）

```
┌ 行情日历页签 ─────────────────────────────────────────┐
│  第一级：月历视图                                      │
│  ┌──────────────────────────────────────────────┐    │
│  │  ‹ 2026年8月 ›      [回到今天]                │    │
│  │  一  二  三  四  五  六  日                    │    │
│  │  27  28  29  30  31  1   2                    │    │
│  │  3   4   5   6   7   8   9   ← 有选股日期淡红背景 │    │
│  │  ...（每格显示当日命中数，如 "7"）               │    │
│  └──────────────────────────────────────────────┘    │
│                                                       │
│  第二级：点击日期 → 当日清单视图（叠层切换，可返回）      │
│  ┌──────────────────────────────────────────────┐    │
│  │  ‹ 返回  2026-08-14（周五）当日选股清单          │    │
│  │  [统一命中列表组件：策略|代码|名称|价格|涨幅|时间|原因] │    │
│  │  行操作：查看K线 / 加入观察池 / 单票诊断          │    │
│  └──────────────────────────────────────────────┘    │
└──────────────────────────────────────────────────────┘
```

### 3.2 数据源（全部来自已有表，无需新存储）

| 数据 | 来源 | 说明 |
|------|------|------|
| 自动命中 | `scan_history` | 每次扫描落库，按 `scan_time` 的日期聚合 |
| 手动选股 | `watch.add_date` | 手动加入观察池的记录，标注来源"手动" |
| 命中策略名 | `scan_history.strategy_name` | 列表直接显示 |
| 分级标注 | `scan_history.reason` | B2"完美/稍欠"等已带在原因里 |

### 3.3 规则（已拍板 2026-08-15）

- **淡红色日期** = 当日有自动命中 **或** 有手动入池记录（用户确认 D013）
- 日期格内显示当日命中数量（如 "7"），鼠标悬停显示摘要（命中 n 只 / 手动 m 只）
- 点击 → 第二级清单：当日自动命中 + 手动入池记录（来源列区分"策略命中/手动"），非交易日为空
- 非交易日（周末/节假日）正常显示但无数据

### 3.4 行情快照服务化（关键技术点）

- 现状：盘中扫描候选（涨幅榜前 N）依赖行情页的 `_last_quotes` 内存快照
- 改造：全市场行情拉取移入后台定时任务（约 30-60 秒一轮，仅交易时段），
  快照存内存 + 沿用 `market_snapshot` 表；扫描中心盘中扫描直接从快照取候选
- **量比/涨速/vol5 预热**：仅服务于行情页的展示列，行情页移除后一并清理
  （`market_tab.py` 删除；`warm_vol5`/`vol5_cache` 相关代码与测试清理；
  若日后要量比再恢复）
- K线图入口：行情页的双击 K 线改由日历清单/观察池/扫描中心的"查看K线"按钮承担

## 四、提醒设置（移至第 3 位 + 策略联动）详细设计

### 4.1 页签位置

观察池之后、策略管理之前（主窗口页签顺序调整）。

### 4.2 新增提醒类型：「策略信号」

用户场景：**"盘中监测到出现符合砖型图或回踩黄线的信号，就提醒"**。

```
类型下拉新增：策略信号
选择策略：下拉列出策略管理中的全部策略（含启用状态标注，如 "砖型图翻红（启用）"）
说明文案：该策略信号命中时触发提醒（复用现有冷却时间机制）
列表描述：策略信号 · 砖型图翻红（启用）
```

### 4.3 联动方式（已拍板 2026-08-15：**B 公式快照 + 策略编号**）

- 提醒创建时：记录 **策略编号 + 版本号 + 公式快照**（冻结）
- 判定：永远用创建时那份公式快照判断；策略后续改动不影响旧提醒
- 新建提醒自然使用策略当前最新版本
- **策略编号（S0001...）作为追溯依据**：即使策略改名，编号不变，
  提醒里的编号 + 版本能精确追溯到"这条提醒基于哪个版本的哪个策略"
  （配合 v0.6.5 策略版本归档，见 5.3 节）

### 4.4 判定引擎（实现要点）

- `alert_engine.py` 新增 `strategy_signal` 分支：用 params 里的**公式快照**，
  对标的的日K（含指标）跑 `formula_signal()`，信号为真即触发
- 检查时机：沿用现有轮询路径（`workers._check_quotes_alerts` 中
  macd/kdj/rsi 的日K检查分支，同款机制，冷却防重）
- 新增提醒类型与现有 6 类并存；推送到托盘 + 微信（沿用现有配置）
- 已修复 B003：提醒 params 落库 JSON 未解析导致提醒检查抛异常的隐藏 Bug

### 4.5 与策略管理/扫描的关系（防混淆）

- 提醒 ≠ 扫描：提醒是"盯特定股票、信号来了叫我"；扫描是"全市场找新票"
- 同一策略可以既被扫描、又被某只观察池股票的提醒引用，互不冲突

## 五、策略管理：策略列表 vs 指标库（回答用户疑问）

### 5.1 两者的本质区别

| | 策略列表 | 指标库 |
|---|---------|--------|
| 存的是什么 | **可执行筛选规则**：公式最后一行是布尔"信号" | **要画出来的线/标记**：公式输出是数值曲线（如白线/黄线/短期线），不是信号 |
| 干什么用 | 扫描中心按节奏跑它 → 产出"命中股票" | 存档原版指标公式 + 说明书，**不参与扫描** |
| 典型例子 | B1海选 / B2普通 / 砖型图翻红（输出 `XG:` 信号） | 黄白线(主图) / 单针下30(副图) / B2类型标记 |

### 5.2 回答你的三个疑问

1. **"指标库是保存我上传的指标的原版内容吗？"**
   是。指标库 = 你的指标原版公式 + 中文说明书 的存档处（你也可以手动新增"指标存档"）。
   注意：原版指标公式常带的绘图指令（COLOR/LINETHICK/STICKLINE 等）
   当前引擎**不生效**（见已知问题 I004），只当注释，所以目前存档≠还原显示。

2. **"指标库在这个系统里有什么作用？"**
   现状（v0.6.3）只有两个实际作用：
   - **存档 + 说明书核对**（保险机制：机器实现 == 你的本意）
   - **一键转选股策略**（"⚙ 转换为策略"：预填指标公式 + 信号模板行，如
     单针下30副图 → 单针下30选股）
   第三个作用（画到K线上人工核对）**要等 T005 实现**，目前缺失——
   所以指标库现在是个"半成品"，这正是之前 known issue I005。

3. **"那它到底该不该留？"** → **已拍板（2026-08-15）：保留，尽快做 T005 画图**，
   让指标库获得第三个作用（画到K线上人工核对）。T005 优先级已提升为 high。

## 五·一、策略编号与版本归档（v0.6.5 已实施）

用户拍板：**每个策略固定编号，编号不变则迭代版本统一归集**。

- **编号规则**：`S0001` 起自增（创建时分配，删除不回收，改名不影响）
- **版本触发**：公式 / 说明书 / 类型变化 → 新版本（v1、v2…）；启停、改名、节奏不产生新版本
- **文件归集**：`archive/strategies/{编号}/v{版本}_{日期}_{名称}.md`
  每个策略一个文件夹，内容含说明书 + 公式原文，删除策略不删归档
- **数据库版本表**：`strategy_versions`（可查询/对比，UI 提供"📜 版本历史"与双版本对比）
- **用途**：① 保险机制补时间维度（改错了可回看旧版）② 提醒快照的追溯依据
  （提醒记"策略编号+版本"，可精确知道当时用的哪版公式）

### Q3 拍板结论（大白话版）

**两种方案的共同点**：提醒都是"信号命中就提醒"——比如你对 000001 建了一条
「砖型图翻红」策略提醒，盘中 000001 满足砖型图翻红条件时就会提醒你。
**这个行为在两种方案下完全一样，跟改不改策略无关。**

**区别只发生在"以后你修改了这条策略的公式"时**：

| 场景 | 方案 A：绑定策略 ID（实时跟随） | 方案 B：保存公式快照 ✅ 已选 |
|------|-------------------------------|---------------------|
| 创建提醒时 | 提醒记下"用 3 号策略" | 提醒记下"当时那份公式 + 编号 + 版本" |
| 盘中判断 | 每次都取策略当前公式判断 | 永远用创建时那份公式判断 |
| 你改了策略公式 | 提醒**自动**用新公式，不用管它 | 提醒**继续用旧公式**，想更新得删了重建 |
| 你删除了策略 | 提醒自动停用，列表标注"策略已删除" | 提醒不受影响（公式已冻结） |

**用户补充**：一般修改完后，新建的提醒自然用新版即可；
同时要求**每个策略固定编号（S0001...），编号不变则迭代版本统一归集**
（v0.6.5 已实施：数据库版本表 + `archive/strategies/` 文件夹归档 + 版本对比 UI）。
